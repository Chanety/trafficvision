# AI+ software & opensource

交通视频预判软件（开发中）。

输入一段 2~30 秒的监控视频，选择 **0.1 / 0.5 / 1 / 2 秒**四档预判梯度之一，
输出标注了目标类型与预判位置的连续视频，并给出可复现的精度评估。

## 当前状态

可运行的命令行版本已完成，并在自采数据集 `videoset_01`（15 段、含 30/60fps 混合、
可变帧率、竖屏、多分辨率）上完成端到端验证。

实测基线（14 段，排除手持抖动片段）：

| 指标 | 数值 |
|---|---|
| 平均目标数/帧 | 8.15 |
| 平均可预判目标数/帧 | 5.05 |
| 1 秒预判误差（平均 / 中位 / P90） | 57.9 / 24.4 / 135.1 px |
| 轨迹中心抖动占每帧位移 | 26% |
| 相对误差中位 | 35% ~ 50% |

## 环境要求

- Python 3.11
- PyTorch **CUDA 版**（本机为 RTX 5060 Laptop，算力 12.0 = Blackwell，必须 CUDA 12.8 以上）
- ultralytics、opencv-python、numpy、scipy、Pillow
- 开放词汇检测需要 `clip` 组件与 `ViT-B-32` 权重（约 338 MB，不入库，首次运行自动下载）

## 使用方式

```bash
python -m trafficvision.cli \
  --video 输入视频.mp4 \
  --horizon 1 \
  --out 输出视频.mp4 \
  --gif 预览.gif \
  --json 逐帧数据.json \
  --weights path/to/yolov8s-worldv2.pt \
  --device 0
```

主要参数：

| 参数 | 说明 |
|---|---|
| `--horizon` | 预判梯度，四选一：0.1 / 0.5 / 1 / 2（秒） |
| `--motion-model` | `auto` 按梯度分工（默认）/ `cv` 图像匀速 / `ca` 匀加速 / `scale` 维度判定 |
| `--tracker` | `bytetrack`（默认）/ `botsort` / `ocsort` / `deepocsort` / `fasttrack` / `tracktrack` |
| `--accel-std` | 过程噪声，越小速度估计越平滑 |
| `--accel-prior` | 速度变化的经验采纳权重（0~1，0 表示完全匀速） |
| `--max-frames` | 只处理前 N 帧（调试用） |
| `--no-timestamps` | 忽略真实时间戳（对照实验用） |

## 关键设计决策与依据

1. **图像坐标系预判，不做标定**：客户视频无标定参数，保证开箱即用
2. **只用历史帧（因果）**：不使用未来帧，避免"用未来推未来"
3. **维度判定 + 归一化匀速**：按目标框高度归一化可消除透视造成的画面内加减速；
   合成受控实验中 0.5~2 秒档误差下降 28%~37%；仅在斜视机位且目标完整可见时启用，
   条件不满足时自动回退匀速模型
4. **跟踪器默认 ByteTrack**：全集实测表明 TrackTrack 虽降低轨迹碎片化 79%，
   但每帧可预判目标数下降 44.6%、误差反而变差，故不采用
5. **时间戳计时**：兼容可变帧率视频

## 已知限制

- 缺少人工标注真值，当前精度评估以"检测器自身未来帧"为参照，无法区分检测抖动与预判偏差
- 相机抖动会显著恶化精度（手持片段误差为固定机位的 2 倍以上）
- **二维平面表达的固有局限**：转弯、掉头等强机动行为在图像平面上表现为速度矢量突变，
  匀速/匀加速模型无法表达，需要引入转弯率或地面平面/三维表达
- 摩托车、自行车等非线性运动目标相对误差最高
- 检测器为通用开放词汇模型，未针对本机位微调，框抖动占每帧位移的 26%

## 后续方向（按优先级）

1. 速度估计的平滑优化（窗口最小二乘 + 按梯度分档调参，无需标注）
2. 检测模型微调（自动预标注 + 人工复核），从源头降低框抖动
3. 检测与跟踪输出分离：所有目标都框出类型，仅稳定跟踪的目标给出预判
4. 机动行为建模：引入转弯率估计或地面平面/三维表达，覆盖转弯与掉头场景
