# 16 · 行人真值问题体检（自动标注的坑）

日期：2026-10-07。用户问"这个疑似真值问题到底是怎么样的"，本文给出实测证据。

## 一、现象

同一个模型（v7）在两个人脸验证集上的行人表现差一倍：

| 验证集 | 真值来源 | 行人 AP50 |
|---|---|---|
| 旧街面 116 帧 | **人工逐帧复核** | 0.72 |
| 新素材 65 帧 | **自动标注**（未复核） | 0.46 |

模型是同一个、推理参数相同，所以差距只能出在真值上。

## 二、实测证据

在新素材验证集上把行人框逐一配对（IoU≥0.5，v7@1280，conf=0.25）：

| 项目 | 数量 |
|---|---|
| 标注框总数 | 278 |
| 模型命中 | 145（52%） |
| 漏检（标注有、模型没有） | **133（48%）** |
| 误报（模型有、标注没有） | 127 |
| **命中框高度中位** | **21 px** |
| **漏检框高度中位** | **46 px** |

**关键异常**：被"漏掉"的标注框（46 px）比命中的（21 px）**大一倍多**。
如果是模型能力问题，应该是小目标漏检更多；这里恰恰相反——
说明那批被漏掉的框根本不是"模型看不见的小人"。

## 三、那些框到底是什么

把样本裁出来看（`outputs\person_gt_check\fn_gt_only.png`、`fp_pred_only.png`）：

**"漏检"的标注框（FN）：几乎全是骑车的人。**
画面里是骑电动车/自行车、打伞的人，自动标注在骑手身上画了一个 person 框。

**"误报"的框（FP）：也是骑车人为主**，另有极少数真实行人（自动标注真漏了）。

这与项目的标注规则直接冲突——

> **规则：先载具、后行人。骑车人、驾驶位里的人只标载具，不标 person。**
> （`trafficvision\labelrules.py` 的 `suppress_riders`，标注工具里对应 `R` 键）

## 四、为什么这些违规框会留下来

`suppress_riders` 的判据是"行人框中心落在**载具框**内且被覆盖比例够大"。
也就是说——**必须先有一个载具框**，规则才能把骑手框删掉。

而这批素材里，自动标注经常**没能给出对应的两轮车框**（远处的小电动车/自行车没检出来），
于是骑手框就没有"载具"可以对消，被原样留在了标注里。
模型训练时看到的是"这个人身上没有车"，推理时又把它当人检出来 → 两边都不一致，
指标自然崩。

## 五、这意味着什么

1. **0.46 这个数不能当"行人检测能力"用**——它主要在衡量"标注对骑手的处理有多乱"。
2. 旧街面那 0.72 是真值，可信；新素材这 0.46 是自动标注的产物，不可信。
3. 连带影响：`docs\14` 效果需求里"行人 0.462 不可用"的结论**需要复核后重写**，
   真实的行人能力可能明显更高。
4. 同理，`nonmotor`（非机动车）类别的真值也可能受影响（骑手框该不该算车，
   两边口径要一致）。

## 六、可以怎么解决（用户决定）

**方案 1：人工清理（最准）**
已备好专项小集，只有 40 帧、全是行人标注最密集的帧，用标注工具按 `R` 清理骑手框即可：
`tools\annotate_person_check.bat`，约 10 分钟。改完我把它合并回主标注集并重算指标。

**方案 2：自动预处理 + 人工抽检（最快）**
我可以写一个增强版清理：对每个 person 框，用**更低阈值 + 多类别提示**
（专门去找 bicycle/motorcycle/nonmotor 的框）判断它是不是骑手，
是就直接删；剩下的再让人工抽查。风险是可能误删"站在车旁的人"。

**方案 3：改标注政策（影响最大，需先想清楚）**
如果产品上"骑手也应该算行人"，那规则就要反过来改：保留骑手框，
并且要把**历史三个数据集**（videoset_01_label、supplement、visdrone）
统一重标一遍，代价很大。**不建议**在没有明确需求前动这条。
