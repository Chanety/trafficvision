# 交通视频预判软件 需求规格

## 一、输入输出契约

| 项目 | 要求 |
|---|---|
| 输入 | 客户提供的一段视频，时长 2~30 秒（超出范围拒绝并提示） |
| 参数 | 预判时间梯度，四选一：**0.1 s / 0.5 s / 1 s / 2 s** |
| 输出 | 一段连续视频（与输入同分辨率、同帧率、同时长） |
| 画面内容 | ① 框出目标并标注类型；② 画出预判时刻的位置 |
| 附加输出 | 每帧结构化数据（JSON）+ 预判精度报告 |

## 二、画面呈现规范

每个目标画三样东西：

1. **实线框 + 类型标签**：当前时刻的检测框，标签形如 `car #3`
2. **虚线框（预测框）**：按所选时间梯度外推出来的位置，标签形如 `t+1.0s`
3. **箭头 + 轨迹尾迹**：从当前位置指向预判位置，尾迹显示最近约 1 秒的运动路径

画面左上角常驻信息条：所选时间梯度、当前帧号/总帧数、当前跟踪目标数。

预测不可靠的目标（刚出现、几乎静止）**只画实线框，不画预测框**，避免给出误导性结论。

## 三、算法方案（关键决策）

### 3.1 在图像坐标系里预判，不做标定

客户给的是一段任意来源的视频，不会提供相机标定参数。所以：

- **默认**：在图像坐标系中做预判（像素），对任何视频都能直接工作
- **可选**：若客户能提供参照物（车道宽度、相机高度），再换算成物理速度

这条决定了软件"开箱即用"，代价是输出的速度只有像素意义。

### 3.2 只用历史帧，不用未来帧

片段虽然离线可得，但预测必须**因果**——只允许使用当前帧及之前的数据。
否则就是"用未来推未来"，指标会好看但不成立。实现上用单侧卡尔曼滤波（匀速模型，状态 = 位置 + 速度）。

### 3.3 为什么用运动模型而不是深度学习预测

预判时长只有 0.1~2 秒，属于极短时外推。这个尺度上匀速/匀加速运动模型的精度，
和需要大量训练数据的轨迹预测网络相当，但算力开销几乎为零、可解释、无训练成本。
后续若要更长时预判（>5 秒）再考虑引入学习型预测器。

## 四、精度如何量化

短片段有个天然优势：**视频自己就提供了真值**。

对第 t 帧的某个目标，其 t+h 时刻的真实位置在同一段视频里是已知的。于是可以逐样本对比：

| 指标 | 含义 |
|---|---|
| 平均位移误差 | 预判位置与真实位置的平均距离（像素 / 相对画面对角线的百分比） |
| 中位误差 / P90 误差 | 抗离群点的稳定性指标 |
| 有效率 | 有多少目标满足预判条件（排除刚出现、静止目标） |

视频末尾 h 秒因为没有未来帧，不参与评分，只参与画面呈现。

## 五、四档时间梯度的预期表现

| 梯度 | 实际含义 | 预期 |
|---|---|---|
| 0.1 s | 几乎等于当前位置 | 误差最小，主要用于展示响应速度 |
| 0.5 s | 短时外推 | 精度仍高 |
| 1 s | 中等外推 | 转弯、加减速会带来明显误差 |
| 2 s | 长时外推 | 误差最大，也是最能体现模型优劣的一档 |

## 六、待定项（后续需要客户确认）

## 六、目标运动状态（constant / variable）

状态是与类别无关的独立属性，规则如下：

| 规则 | 说明 |
|---|---|
| 判定 | 目标在**连续 6 帧**内位置未变化 → `constant` |
| 表现 | `constant` 状态**暂不显示**（不画框、不参与预判） |
| 恢复 | 重新移动后恢复显示并重新框选，状态回到 `variable` |
| 豁免 | `sign`（标志牌）与 `bollard`（路桩）不受此规则约束，始终显示 |

实现位置：`trafficvision/state.py`；参数 `STILL_WINDOW`（连续帧数）与
`STILL_THRESHOLD_PX`（位置波动阈值）在 `trafficvision/config.py` 中可调。
判定结果写入输出 JSON 的 `state` / `hidden` 字段。

## 七、待定项（后续需要客户确认）

1. 目标类型范围：默认 car / truck / bus / motorcycle / bicycle / person，是否需要增删
2. 是否需要物理速度（km/h），若需要则要提供参照物或标定
3. 是否需要事件输出（逆行、违停、超速），当前版本只做预判与呈现
4. 输出视频编码格式与分辨率要求
