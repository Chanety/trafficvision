## 四、怎么读这些数字（重要）

**跨类别方案的 mAP 不能直接比大小。** 合并本身就会让指标上升，因为
"把自行车认成摩托"这类家族内混淆不再算错误了。真正可比的是**没有参与合并的那些类**：

| 可比类别 | 新素材（v6→v7） | 旧街面（v6→v7） |
|---|---|---|
| 汽车 | 0.872 → 0.880 | 0.874 → 0.859 |
| 卡车 | 0.274 → 0.281 | 0.654 → 0.601 |
| 公交 | 0.735 → 0.739 | 0.913 → 0.899 |
| 行人 | 0.391 → 0.417 | 0.718 → 0.716 |
| 标志牌 | 0.394 → 0.548 | （无真值） |
| 路桩 | （无真值） | 0.423 → 0.445 |

结论：合并没有拖累其他类别，新素材上标志牌还涨了 15 个点；旧街面卡车/公交
回落了 1~5 个点，属于训练集配比变化的正常波动。

合并最大的收益在最弱的两个类上：**自行车从 0.05~0.14 提升到 0.56~0.64**
（因为它现在只要能认出"两三轮车"就算对，不再要求区分摩托/自行车/三轮）。
代价是产品端不再输出三者的细分标签。

## 五、端到端验证与新发现

用 v7 权重实际渲染了 `videoset_02_origin\VID_20261004_112333.mp4` 前 90 帧：
输出正常，`nonmotor` 出现在结果里（270 个框），说明软件侧的类别过滤问题已解决。

但这次发现一个**比类别合并更值得关注的问题**：同一段视频上，
1 秒预判误差中位 **69.6 px**、均值 177.6 px，而旧素材上只有 5~15 px。
排查过程：

1. 先怀疑是我改的类别处理引入的，用 v5 模型在**同一段视频**上复测：
   中位 46.5 px、均值 155.6 px —— 同样很大，**不是改动引入的**。
2. 再查相机运动：这段素材全局位移平均 0.11 px/帧（旧素材 0.06~0.10），
   **不是相机抖动造成的**。
3. 按类别/速度拆解（v7，284 个样本）：

| 分组 | 样本 | 平均误差 | 中位 | P90 |
|---|---|---|---|---|
| 汽车 | 163 | 277.5 | 178.9 | 455.4 |
| 公交 | 55 | 54.0 | 41.5 | 116.9 |
| 标志牌 | 51 | 45.6 | 45.6 | 67.4 |
| 路桩 | 12 | 12.3 | 11.3 | 16.9 |
| 快速 >150 px/s | 165 | 226.6 | 97.9 | 438.3 |
| 慢速 <50 px/s | 87 | 91.3 | 42.6 | 328.6 |

即：误差高度集中在**汽车**上，而且汽车的中位误差（178.9）比"快速目标"分组
的中位（97.9）还大，说明里面混着一批极大的异常值。
最可能的原因是**跟丢后重新关联（ID 切换）或目标出画/被遮挡**，
而不是运动模型本身算错——这一条需要下一步专门验证。

## 六、下一步

1. **查清 1 秒误差的来源**：区分"运动模型算不准"与"跟踪 ID 切换/出画"。
   做法：把误差样本按"预测时目标是否仍在画面内、是否发生 ID 变更"分类统计。
2. 若确认是 ID 切换为主，优先改跟踪与遮挡处理，而不是调运动模型。
3. 三轮车细分能力已随合并取消；若以后仍需要区分三轮车，需要单独一类重训。
4. 新素材的 332 帧人工复核仍可做（工具已就绪），做完可量化自动标注的代价。
