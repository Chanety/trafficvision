处理（用户 2026-10-10 指示"线上的东西清理掉、不合理的转线下"）：

1. `git filter-repo --path dataset_batches/ --invert-paths` 把 `dataset_batches/` 从**全部历史**里摘掉；
2. 删除远端分发分支 `codex/dataset-batches-v1`（分支唯一的用途就是放包，内容可从本地重生成）；
3. 批次包改为**线下转发**（负责人直接发 zip，工具改成 `tools\dataset_batches\解压批次.bat`）。

| 指标 | 清理前 | 清理后 |
|---|---:|---:|
| 本地 `.git` | 524.6 MB | **13.6 MB** |
| 远端普通 clone | ~520 MB | **28.8 MB**（最大对象是 docs 里 3.3 MB 的 UI 截图） |
| 仓库里是否有批次包 | 有 | **无**（`dataset_batches/` 已不在任何提交里） |

> 遗留一条：GitHub 上那个批次包的 PR（`refs/pull/1/head`）仍指向被删分支的提交，
> 服务端对象要等 GitHub 自行 GC（普通 clone 不会拉它，不影响任何人）。
> 做镜向 clone（`--mirror`）时会带上，实测 277.7 MB。
> 想彻底清掉得在网页上关闭/删除那个 PR，必要时找 GitHub 支持强制 GC。

另有一条硬前提：仓库现在是**私有**的，而赛事要求成果链接"评审期内持续有效、可访问"。
所以要么把仓库转公开，要么把 `reviewer` 包放网盘（报告里给下载地址 + SHA-256）。
这条是对外可见性的决定，没有替你做。

## 五、报名系统的评审材料（另一条口径，硬上限）

| 材料 | 上限 | 实测/推算 |
|---|---|---|
| 技术报告 PDF | 正文 ≤15 页、**≤10 MB** | docs 里 UI 截图单张 0.6~3.3 MB，直接贴 4 张就爆；先压到 200~300 KB/张，正文写完大约 2~5 MB |
| 演示视频 MP4 | 3~5 分钟、**≤300 MB** | **风险在这里**，见下 |

演示视频的体积风险（实测）：软件自己导出的 mp4 用的是 `mp4v` 编码，
1920×1080 实测 **12.7 MB / 5.0 s = 2.55 MB/s**，照这个码率：

- 3 分钟 ≈ **459 MB**，5 分钟 ≈ **764 MB** → **直接导出会超 300 MB 上限**。
- 需要按 H.264 重编码（CRF 23 大约 0.4~0.8 MB/s），3 分钟落在 **70~140 MB**，5 分钟 120~240 MB，都在限内。
- 本机 PATH 里没有 ffmpeg；可用 bilibili 自带的
  `<用户目录>\AppData\Roaming\bilibili\ffmpeg\ffmpeg.exe`，或 `pip install imageio-ffmpeg`。

## 六、关于 413（请求体过大）

413 是"服务端单次请求体超过上限"，和包的类型无关，只和**那一次上传的东西多大**有关：

- 整个项目 9.11 GB、`datasets/` 4.59 GB 这种量级，任何上传表单/接口都过不去。
- 现在这三个包 **5.3 / 18.2 / 46.8 MB**，网盘、GitHub Release（单文件上限 2 GB）、
  报名系统表单都不该再触发 413。
- GitHub 侧的边界是：**单个文件 >100 MB 会被拒**（历史里的 batch zip 是 76 MB，没超），
  仓库打包超过 2 GB 的 push 会被拒——`.git` 354 MB 还够不上。
- 如果那次 413 是发生在别的地方（某个接口、某次上传），把地址和上传物告诉我，我按它的上限切包。

## 七、两个评审体验问题（这次实测中发现并已修）

1. **中文 Windows 控制台跑 `--help` 会崩。** 帮助文本里有 `px²`，控制台默认 GBK 编码，
   `UnicodeEncodeError` 直接把进程打死——评审拿到包后敲的第一条命令就踩雷。
   已在 [trafficvision/cli.py](../trafficvision/cli.py) 的 `main()` 里加 `errors="replace"`：
   不动编码（中文显示不受影响），只把编不出的字符降级，`--help` 现在正常输出。
2. **缺 CLIP 权重时报的是一句原始 RuntimeError**（`Model ... not found; available models = [...]`），
   日志里显示"上下文校验: 失败"，看着像程序坏了。实际是语义校验这一步跳过、静态地图照常工作。
   已改成明确提示 + 官方下载地址，并把它标成"**跳过**"而不是"失败"（`trafficvision/verify.py`、
   `pipeline.py`、`cli.py`）。
3. 如实记录：第 2 条改动我自己引入过一次回归（新增的异常类型没在该作用域导入，
   静态通道会以 `UnboundLocalError: source` 崩掉）。已修复，并在**重新打包后的成品包**里复测通过。
