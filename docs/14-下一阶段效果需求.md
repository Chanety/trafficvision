# 14 · 基于 videoset_02 的下一阶段效果需求

日期：2026-10-05。这份文档回答用户最初提的问题："针对新数据集训练完，下一步的效果需求是什么。"
所有"当前值"都是在 `videoset_02`（用户的真实素材）上实测得到，不是估算。

## 一、依据与口径

| 项目 | 说明 |
|---|---|
| 检测评测集 | `videoset_02` 留出的 3 段视频共 65 帧，1528 个真实框 |
| 预判评测集 | 6 段视频 × 300 帧，v7 权重，imgsz 1280 |
| 类别口径 | 7 类（摩托车/自行车/三轮车已合并为"非机动车"） |
| **重要前提** | 当前验证真值来自**自动标注**，存在循环论证风险；用户的人工复核报告到位后，下表数字需要重算 |

## 三、效果需求（建议值，待你确认）

### A 档：现阶段可以承诺的水平

| 指标 | 目标 | 当前 | 状态 |
|---|---|---|---|
| 汽车 / 公交 / 标志牌 AP50 | ≥ 0.70 | 0.88 / 0.76 / 0.87 | ✅ 达标 |
| 非机动车 AP50 | ≥ 0.55 | 0.57 | ✅ 刚达标（融合可到 0.65） |
| 0.1 s 预判中位误差 | ≤ 5 px | 4.3 px | ✅ |
| 0.5 s 预判中位误差 | ≤ 20 px | 16.4 px | ✅ |
| 1 s 预判中位误差 | ≤ 35 px | 31.2 px | ✅ 临界 |
| 2 s 预判中位误差 | ≤ 80 px | 75~78 px | ✅ 临界 |
| 每帧可预判目标 | ≥ 12 个 | 17.0 个 | ✅ |
| 轨迹跳变率 | ≤ 60 次/千帧 | 50.6 | ✅ |

**含义**：以"车、公交、非机动车"为主要目标、以 0.1~1 秒为主要梯度的场景，
现在这套模型可以直接交付试用。

### B 档：要达到"好用"还缺什么

| 差距 | 当前 | 建议目标 | 差距 | 达成路径（按性价比） |
|---|---|---|---|---|
| 行人检测 | 0.462 | ≥ 0.70 | 大 | ①新素材行人实例仅 278 个，需补标注/补拍；②SAHI 切图推理专治小目标；③两者叠加 |
| 卡车检测 | 0.285 | ≥ 0.60 | 大 | 实例仅 46 个，属于数据量问题，先补样本再谈模型 |
| 非机动车 | 0.568 | ≥ 0.75 | 中 | ①v7+v8s 融合已实测到 0.654；②继续补两三轮车素材 |
| 1 秒预判 | 31.2 px | ≤ 25 px | 中 | **目前无已知技术路径**（见第五节），建议改为"分梯度承诺" |
| 2 秒预判 | 75~78 px | ≤ 60 px | 中 | 同上 |
| 跳变率 | 50.6/千帧 | ≤ 30/千帧 | 小 | 继续收紧串轨判据 + ReID 只用于接断轨场景 |

### C 档：产品侧承诺（不依赖模型精度，成本低，建议优先做）

1. **分梯度承诺**：0.1/0.5 秒可以承诺"框的位置基本可信"；1 秒标"参考"；
   2 秒标"仅示意方向"。这与实测误差曲线一致，也避免用户按统一标准验收。
2. **低置信标注**：机动（转弯/变道）目标的预判框已经用灰色虚线 + "机动·低置信"标出，
   建议在交付说明里写明这条规则。
3. **遮挡续推**：目标被遮挡时框会继续外推（虚线 + "遮挡续推"），
   实测续推样本的误差中位 29.3 px，比实测样本的 33.5 px 还好，可以放心展示。

## 四、验收方式（建议写进交付）

1. **验证集要与训练集分离**：用 `videoset_02` 留出的 112844 / 113037 / 114022 三段，
   人工复核后作为验收集；样本量建议 ≥300 帧（当前 65 帧，稀有类统计噪声大）。
2. **检测**：按类别报 AP50 与实例数，实例数 <50 的类别（卡车、公交、标志牌）
   结论要标注"样本不足"。
3. **预判**：报四个梯度的中位/均值/P90、每帧可预判目标数、轨迹跳变率，
   并说明用的是哪套运动模型与跟踪参数（命令行可复现）。
4. **对比必须同集**：项目已有 `bench\eval_compare_models.py`、`bench\tracker_bench.py` 等工具，
   跨验证集的数字不可比（这一点在早期踩过坑）。

## 五、明确不建议再投入的方向（都有实测证据）

| 方向 | 证据 | 结论 |
|---|---|---|
| 圆弧/CTRV 外推救转弯目标 | 阻尼转角扫描里 gain=0 每档最优，急转档 69→164 px（docs/10） | 死路 |
| IMM 多模型自适应滤波 | 8573 样本配对实测，IMM 更准的只占 50%，整体打平偏负（docs/11） | 死路 |
| 调卡尔曼过程噪声 | 降到 100~200 只让中位好 5%，P90 反而差 3~8%（docs/11） | 得不偿失 |
| 换跟踪器（BoT-SORT+ReID / OCSORT / 长缓冲） | 同一批目标上中位误差只差 1~3 px（docs/09） | 无效 |
| 继续提高推理分辨率 | 1600 在两个验证集上都比 1280 差（docs/11） | 无效 |
| 换更大的检测模型 | yolo11s 目标域 0.597 < yolo11n 链式 0.637（docs/12） | 无效（但精确率更高，取向不同） |

**一句话**：误差已经不在"算法选得对不对"，而在**小目标的数据量**和
**1~2 秒尺度上世界本身的变化**。前者靠标注/素材，后者靠产品侧的期望管理。
