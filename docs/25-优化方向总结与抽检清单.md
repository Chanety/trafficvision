# 25 · 优化方向总结与抽检清单

日期：2026-10-10。承接"BEV / 其他方法能否替代线性预判"的讨论，
把已验证的边界、还没做的方向和抽检方式固定下来，避免重复投入。

---

## 一、已证死的路线（不要再投人天）

全部是实测负结果，依据见 `docs/15`、`docs/18`、`docs/项目状态与实验记录.md`：

| 路线 | 实测结论 |
|---|---|
| 匀加速 CA | 比匀速差 3~8 倍（加速度估计被检测抖动主导） |
| 圆弧外推 CTRV | 阻尼转角扫描里 gain=0（纯匀速）每一档最优 |
| IMM 交互式多模型 | 8573 样本：更准的样本仅 50%，中位/均值/P90 全面略差 |
| 自适应卡尔曼（NIS 在线调 Q） | P90 从 116.6 恶化到 125.8，没打破"中位 vs 尾部"两难 |
| 地面平面 BEV（实验 C） | 中位 34.6→45.9，均值 57.7→167.1；连"深度变化 >60px"该赢的场景也只赢 29% |
| 切图推理（SAHI 标准后处理） | 整体 −2.5%~−6%，只有非机动车略升 |
| 提分辨率 1600 / 换 yolo11s | 都变差（"加算力换精度"连续三次失败） |
| 换跟踪器（TrackTrack 等） | 可预判目标数降 44.6%，误差反而变差 |

**结论**：短时（≤2 秒）、单目、无地图无交互的设定下，匀速卡尔曼就是强基线，
这与 Schöller 2020 的公开复现结论一致（见 `docs/20`）。精度投入的边际收益已很小。

## 二、还能做、且预期收益为正的方向

### P0 · 提交前可做（低风险、无需新素材、无需新依赖）

| # | 方向 | 为什么值得 | 成本 |
|---|---|---|---|
| P0-1 | **按预判梯度分档调参** | `docs/03` §3.3 已实测：Q=50 时 1s/2s 最好，Q=800 时 0.1/0.5s 最好；但 `config.py` 至今只有一套全局 `accel_std=400`。落地后 1s 中位可降约 15%、2s 约 14%（旧素材口径，需在 videoset_02 重测） | 0.5 天 |
| P0-2 | **幽灵续推收口** | 实测 64% 的续推目标此后再未出现（画出"跟着走但没人"的框）。已加"出画即停止续推"判据，需确认效果 | 0.5 天 |
| P0-3 | **静态地图缓存提速** | 命中场景先验后 0.53 → 约 0.09 s/帧。演示视频录制与"运行高效稳定"评分直接相关 | 已实现，需验证 |
| P0-4 | **独立真值验证**（`docs/22`） | 现有预判误差真值取自同一跟踪器的未来帧，属自证式；人工真值可同时给出中心误差与**框 IoU**，直接对应 25 分"可核验效果" | 1 天（最小可交付：1 段 100 帧） |

### P1 · 有余量再做

| # | 方向 | 说明 |
|---|---|---|
| P1-1 | 小目标数据补齐 → 重训 | 行人 0.462 / 卡车 0.285 不达标，根因是实例太少（行人 278、卡车 46），不是模型结构问题 |
| P1-2 | 全局运动补偿 GMC | 走路拍摄（3~9 px/帧）误差涨 2.4~5.3 倍，且静止目标抑制会失效；当初因相机静止把 GMC 关掉了 |
| P1-3 | 速度估计的滑窗最小二乘平滑 | 与 P0-1 同源，可一起做 |
| P1-4 | 机动意图分类 → 分模式预测 | 转角速度对误差有解释力（直行 35px → 急转 62px），但没有车道几何，特征受限，收益不确定 |

### P2 · 需要新条件才成立

| # | 方向 | 前置条件 |
|---|---|---|
| P2-1 | **相机标定 → BEV + 米制速度** | 需要棋盘格或已知长度标线的素材。固定机位做一次即可，顺带能输出 km/h 真实速度（对交付是额外价值） |
| P2-2 | 学习式 BEV 感知（BEVFormer / LSS / BEVDet 类） | 需要多相机 + 精确内外参 + nuScenes 级标注 + 大算力；单目未标定不成立，且短时域打不过匀速 |
| P2-3 | 学习式轨迹预测（LSTM / Transformer / 多模态） | 需要地图与交互上下文；无这些条件时收益为负 |

## 三、抽检集怎么用

生成：`python tools/make_product_samples.py --batch N`（默认 20 张一批，按视频轮换）

每批产出在 `outputs/spotcheck/batch_NN/`：

- `01.png … 20.png`：软件**实际输出画面**（实线检测框、类型、预判虚框＋箭头、
  静态记忆框、HUD）
- `原始帧/01.png …`：同一帧的原始画面，用来判断有没有漏掉的目标
- `总览.jpg`：20 张拼成 4×5 大图，先扫一遍
- `索引.md`：每张的来源视频、帧号、时间点、目标数/可预判数/记忆框数/类别分布

回报问题时按编号描述即可，例如：

- `07 公交漏了` / `12 那根路桩是误检（其实是花坛边缘）`
- `03 骑车的人被标成行人`
- `09 预判框方向反了` / `15 框跟着走了但画面里没人`
- `11 一辆车画了两个框`

这些反馈会直接对应到上面的优化项：漏检→P1-1；误检/记忆框→P0-3、静态通道；
类别错→标注规则；预判方向→运动模型（P0-1）；幽灵框→P0-2；重复框→NMS。
