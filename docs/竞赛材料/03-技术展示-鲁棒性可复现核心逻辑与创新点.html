二、核心逻辑

输入一段 2~30 秒监控视频 + 选一个预判梯度，输出带类型与预判位置的连续视频，并自动给出可复现的精度报告。

2.1 主链路：六环，任一环失效都会污染结果

1 检测
开源检测模型输出目标框与类别
→
2 跟踪
跨帧关联成轨迹；串轨防护切断错关联
→
3 运动估计
因果卡尔曼滤波（只用当前帧及之前）
→
4 外推
0.1/0.5/1/2 秒四档；机动目标降置信
→
5 呈现
实线检测框 + 虚线预判框 + 尾迹箭头
→
6 自评
用视频自己的未来帧做真值，输出误差报告
三条设计原则：① 因果——只允许使用当前帧及之前的数据，否则就是"用未来推未来"； ② 图像坐标系、不做标定——客户视频拿不到相机参数，保证开箱即用； ③ 分梯度置信——不同时间梯度的可信度完全不同，不能给一个笼统的精度承诺。

2.2 静态通道：两段式判据 + 场景先验预计算

这是本项目与"每帧重新检测"的主流做法差别最大的地方。监控摄像机长期不动， 场景里大量结构（路桩、标志牌、信号灯、路灯）位置固定，但单帧检测会反复漏掉它们 ——一辆公交开过、一个行人走过，柱子就从画面上消失了。

① 多提示词扫描
同一概念配多个提示词（bollard / concrete bollard / barrier post），低阈值召回优先
→
② 跨帧一致性投票
非遮挡帧里 ≥80% 被识别为同一类 → 写入隐标记
→
③ 语义校验
连周围一起裁出，零样本图文匹配判断"到底是什么"，排除路缘石/广告牌
→
④ 落盘为场景先验
每个机位一份文件；之后每段视频直接加载
→
⑤ 在线查表注入
本帧检测器漏掉且未被遮挡 → 按先验补回，标注"·记忆"且不做预判
为什么必须是两段式。投票只回答"这个位置稳不稳定"，回答不了"这到底是什么"。 花坛边缘、路缘石、广告牌同样常年不动，一样能通过 80% 一致性检验。 加上语义校验后，实测把用户标出的 6 个误检全部拦下——其中 2 个是模型独立给出的判词 （"贴着花坛的涂装路缘石""建筑上的大型文字广告牌"），与用户判断一字不差。
判决规则整体偏向保留。误删一个真目标的代价（用户最初的抱怨）远高于留一个误检 （清单上扫一眼就能划掉）。所以只有证据确凿的才直接否掉，拿不准的一律降级为"待确认" 交给人看——尺寸问题只降级、不删除，因为实测"最小边 ≥16px"这类硬阈值会连带 杀掉远处 12×66px 的真路灯。

三、创新点构造

每条按「上游做法 → 我们的做法 → 证据 → 边界」四段式写。边界那一栏不是客套，是答辩时最容易被追问的地方。

创新点 1 · 场景先验预计算：把"不变的部分"从在线推理里剥离
上游做法
每帧独立检测，漏了靠跟踪补；提精度靠加算力（更大模型、更高分辨率、切图推理）
我们的做法
离线用多帧投票 + 语义校验把场景中不变的结构固化成一份"场景先验"，在线只做一次查表注入。提精度靠搬算力——把贵的部分搬到离线
证据
近景并排的路桩，主模型对左侧那根连 0.01 置信度都没有（它的训练标注里从来就没有这根柱子）；场景先验把它稳定补回。 缓存后 318 → 81 ms/帧（3.9×），且注入结果逐位一致（1367 = 1367）
边界
仅适用于固定机位；先验文件按机位一份，换机位需重算（重算成本已由缓存摊薄）。目标必须长期静止——停靠过久的车辆部件（如公交车窗立柱）会被误固化为静态结构，这类需靠语义校验或人工复核剔除
创新点 2 · 两级静态目标判据：位置一致性 + 语义一致性
上游做法
单帧置信度阈值（我们的自动标注流程原本用单词提示词 + 0.15 阈值）
我们的做法
第一级：跨帧一致性投票（非遮挡帧 ≥80%）回答"稳不稳定"；第二级：零样本图文匹配（正例/反例词表）回答"是什么"。两级正交，缺一不可
证据
单词提示词 "bollard" 对混凝土路桩只有 0.02~0.16 分，换 "concrete bollard" 立刻 0.55~0.91； 两级过滤后位置清单从 282 条降到 136 保留 / 63 待确认 / 83 否掉，用户标注的 6 个反例全部拦下
边界
零样本判别对极小目标不可靠（几十像素的框连人都认不出），这类只能降级为"待确认"； "稳定存在"的误检（如常年不动的红色招牌）仍会通过投票，需要人工复核兜底
创新点 3 · 用系统性负结果划定能力边界，而不是只报指标
上游做法
文献方向普遍指向更复杂的模型：圆弧/CTRV 外推、IMM 多模型滤波、自适应卡尔曼、地面平面（BEV）建模、更大检测模型、切图推理
我们的做法
把上述路线逐条实装并做配对实测，用同一批目标、同一时刻比较，把"哪条路走不通、差多少"写成可复现的结论
证据
12 条路线全部否掉：圆弧外推每档最优都是 gain=0；IMM 在 8573 配对样本上更准的只占 50%； BEV 在它"本该赢"的深度变化档输得最多（61.9 → 94.1 px）；换更大模型没有赢（0.597 < 0.637）。 结论与文献一致——短时域上匀速基线就是强基线
边界
结论限定在单目、≤2 秒、无地图与交互信息的设定下；有真实相机标定或车道几何时不适用
创新点 4 · 分梯度置信承诺：把"预测不准"变成可管理的产品设计
上游做法
给一个笼统的精度承诺，用户按统一标准验收
我们的做法
按梯度给不同承诺（0.1/0.5 秒"位置可信"、1 秒"参考"、2 秒"仅示意方向"）； 机动（转弯/变道）目标用灰色虚线标"低置信"；被遮挡时框用虚线标"遮挡续推"
证据
实测误差曲线本身就是分档的：4.3 / 16.4 / 31.2 / 75~78 px。承诺与数据一一对应，不是话术
边界
这是期望管理而非精度提升；2 秒档的绝对误差没有已知技术路径能显著压低
对照赛事红线自查：规则写明"仅调用通用模型接口、直接部署现有开源项目、复制模板、 简单拼接功能或更换界面，且未形成实质改进的，原则上不认定为充分创新"。 本项目的自研边界是清楚的——预判链路、静态目标两段式机制、场景先验固化和复用、 评测体系与数据集建设全部自主完成；第三方资源只提供通用能力（检测、跟踪、滤波、数值计算）， 且逐项列在《开源及第三方资源使用清单》里。

4.1 受控抖动注入实测

往最稳的素材里注入已知幅度的随机抖动，逐档测量。结论：站立手持（≤1 px/帧）精度基本不受影响， 但静止目标抑制会失效（判定为静止的目标占比从 72% 掉到 37%），画面会变乱；走路拍摄（3~9 px/帧）误差涨 2.4~5.3 倍。

五、可复现性

"可核验的效果数据"是评分里权重最高的一项（25 分）。这一节说明每个数字是怎么来的、别人怎么重跑。

5.1 三条硬规矩

  1. 同集同参才能比。项目早期踩过坑：v1 在旧验证集上显示 0.612，换到统一验证集后只有 0.210。 此后所有版本对比都在同一份验证集上用同一脚本重跑，表格里标注验证集与分辨率。
  2. 按视频划分，防止泄漏。曾因从全部视频挖补充样本造成验证集泄漏、指标虚高； 现在数据集构建脚本内置"按视频排除验证集"逻辑。
  3. 区分实测事实与推测。负结果同样写入记录，且标注数据来源与测量条件。

5.3 可复现性的一次直接验证：场景先验缓存

同一段视频（120 帧）：首次现场计算场景先验 318 ms/帧；把它落盘后第二次运行命中缓存， 81 ms/帧（3.9×），且两次的注入框数量逐位一致（1367 = 1367）。 这既是性能优化，也证明"先验固化"这一步是无损的。

七、目前的短板与应对

这一节不是自谦，是把答辩时会被追问的点先摆出来，并说明已经采取或计划采取的措施。

短板具体情况应对
预判误差是自证式的 真值取自同一个跟踪器的未来检测：跟踪漂移时真值跟着漂移，指标"自洽但不一定真实"。从未用独立来源验证过 计划人工标注若干段连续帧做独立真值对照；材料中已如实标注该限制
只评了中心点，没评框 产品画的是框，但所有指标都是中心点距离；预测框的尺度误差从未测量 计划补充 IoU / 尺度误差指标
行人 0.462 / 卡车 0.285 两类都不达标。行人偏低还叠加了真值问题（自动标注把骑手标成了 person）与"过小目标过滤"的双重影响 真值清洗 + 补标注/补拍；并且需要明确效果指标按"过滤前"还是"过滤后"验收（两条要求目前不能同时成立）
类别口径未定 最新模型 7 类，而数据集已按 10 类重标（新增路灯/信号灯、骑车人单列）。静态先验还会注入模型根本预测不了的类别 需在"用新标注重训一版"与"回退 7 类口径"之间拍板
样本量小、无置信区间 融合 +3%、非机动车 +11% 这类结论基于 65 帧 / 116 个实例，未做显著性检验，结论强度被高估 扩大验证集；报告中给结论标注样本量
没有外部背书 无论文、无专利、无企业合作、无示范应用——赛事规则已明确这些不作为评分依据 把投入放在"可核验效果数据"与"开放成果"上，这是权重最高的两项
AGPL-3.0 许可链 检测与跟踪依赖是 AGPL-3.0，且微调权重属衍生作品；规则对许可证重大违规是一票否决 作品整体以 AGPL-3.0 开放——既合规，又同时满足"必须形成开放成果"的要求
一句话总结：这个项目最扎实的部分是可核验的实验密度——12 条路线的证伪地图、 9 个模型的同集对比、静态目标的两级判据与先验复用；最薄弱的部分是真值的独立性与 小样本结论的强度。前者需要人工标注几段连续帧来补，后者靠扩大验证集。
