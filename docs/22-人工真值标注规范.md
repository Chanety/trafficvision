# 22 · 独立人工真值：标注规范与验收口径

日期：2026-10-09。对应仓库审计 P0-02、用户决定"前置"。

## 一、为什么必须做，以及为什么不是"再标点图"那么简单

现在所有预判精度数字的真值，都来自**同一个跟踪器的未来检测帧**。这意味着：

> 跟踪漂移时，"预测"和"真值"会一起漂——指标看起来自洽，但不一定真实。

这是本项目在比赛里最容易被追问的一点（"可核验的效果数据"占 25 分）。
已有的 `docs/16、17` 用"误差方向比"证明了**检测**真值有问题，
但**预判**真值的问题只能靠独立来源解决。

## 二、标注什么：**带 ID 的连续片段**

最容易搞错的一点：**不能再标离散单帧**。

预判评测要回答"这个目标 1 秒后在哪"，所以必须知道"1 秒后的那个框是不是同一个目标"。
没有 ID 就无法建立这个对应关系。因此：

| 要求 | 说明 |
|---|---|
| 连续帧 | 每段 100~200 帧连续标注，不能隔帧抽样 |
| **稳定 ID** | 同一目标跨帧用同一个 id；目标消失后不再复用该 id |
| 只标"值得预判"的目标 | 画面里的**运动**车辆/两三轮即可，静止停放的车、路桩、行人不必全标——省一大半工作量 |
| 至少 3 段 | 覆盖不同场景，建议：直行主路、路口转弯、有遮挡+远处小目标 |

## 三、格式

MOT 风格，纯文本，一行一个框：

```
frame,id,x,y,w,h,cls
```

- `frame`：帧号，**从 0 开始**，与视频对齐（不是秒）；
- `id`：目标编号，同一目标跨帧不变；
- `x,y,w,h`：像素坐标，左上角 + 宽高（**不是 YOLO 的归一化中心点格式**）；
- `cls`：类别名，必须与项目类别表一致（当前生产口径 10 类，见
  `schemas/classes_v3_10.yaml`）：`car / truck / bus / nonmotor / person / sign / bollard / roadlamp / trafficlight / rider`

示例：

```
0,1,820,470,180,120,car
1,1,812,469,181,121,car
2,1,803,468,182,121,car
0,2,1310,505,90,110,nonmotor
```

## 四、怎么用（评测脚本已就绪）

```bash
python bench/eval_manual_truth.py \
    --video 片段.mp4 --truth truth/segment01.txt \
    --weights outputs/train/v7/weights/best.pt \
    --horizon 1 --out outputs/manual_eval_seg01.json
```

脚本的评测逻辑刻意避免循环论证：

1. 在**当前帧 t**，用 IoU≥0.5 把模型检测框与人工框配对——两边都是同一时刻的
   **观测对观测**，不是预测，因此这一步不引入循环；
2. 沿人工 id 找到 **t+h 时刻**的人工框，这就是独立真值；
3. 比较模型在 t 时刻给出的"t+h 预判框"与该人工框。

输出：中心误差（中位/均值/P90）、**预测框 IoU**（此前从未测量过）、按类拆分。

## 五、这一份真值能顺带解决三件事

| 问题 | 怎么解决 |
|---|---|
| 预判误差自证式 | 真值来自人工，与跟踪器无关 |
| 只评中心点、没评框尺度 | 脚本同时报 **IoU** |
| "可核验效果数据"缺独立证据 | 每项指标可追溯到：视频、真值文件、权重 SHA-256、命令行 |

## 六、最小可交付（如果时间紧）

**一段视频、100 帧、只标 5~10 辆运动中的车**，就能给出第一份独立预判误差——
这已经足以在报告里写"我们用独立人工真值验证过"，而不必等全量标注完成。
